# 沙盒实现与模拟：可靠性门控的节点知识（2026-11-01）

本文件记录 [`model_direction.md`](model_direction.md) 中模型的第一版实现，以及在 CPU 沙盒中的两组实验：合成数据（结构已知）和 FeederBW 的一个测量分包（40 条馈线）。

- 代码：newpapercode `rnk/`（说明见 `rnk/README.md`）、`run_rnk.py`、`scripts/run_rnk_sim.sh`、`scripts/run_rnk_feederbw.sh`、`tools/rnk_tables.py`、`tests/test_rnk.py`
- 原始结果：本仓库 `results/rnk_sandbox/`
- 骨干：全局 MLP（CPU 上训练快）。论文中的主骨干（带协变量的全局 Transformer）留到 GPU 上做。

## 1. 实现

| 模块 | 实现 |
|---|---|
| 归纳式节点知识（NKE） | 描述信息 MLP + 近期画像 MLP（过去 28 天按"星期 × 小时"的均值，168 维）+ 残差身份；节点知识经零初始化的 FiLM 进入骨干第一层 |
| 协变量一致分解（KCD） | 8 个共享基函数（协变量和日历的小 MLP），系数 = $\beta_0$ + 节点知识的线性函数；每类设备一个"每单位容量的响应"（单调设备用 softplus 保证符号不变）× 假设的容量。$u$ 从回看窗口中扣除、预测后加回 |
| 投运后验 | 单变点模型：每天的统计量 = 晴天中午负荷 − 夜间负荷（以 $\sigma$ 为单位），投运后按登记容量 × 0.8 × 辐照下降；先验为 Gamma(2, 25 天) 的时滞分布；似然乘 0.5（残差相关）；用累计和对每个预测日求后验 |
| 可靠性门控（KRG） | 见下文"与设计的差异" |
| 训练 | Adam，学习率 1e-3，每 10 轮减半；权重的指数滑动平均（每步 0.99），用平均后的权重做验证和早停；最多 40 轮 |

**与设计的差异**（都来自沙盒中的发现）：

1. **门控只作用于"依赖状态持续"的知识**：身份乘以 $q$；28 天画像与 14 天短画像按 $q$ 混合（$q\pi_{28}+(1-q)\pi_{14}$）。描述信息和 KCD 不受门控。
   - 原因：最初把全部节点知识都收缩到总体平均时，未记录变化后的误差反而从 0.031 升到 0.043。描述信息（台账）和近期画像在变化后仍然有效，真正过时的是身份和长窗口画像。
   - 训练时以 0.2 的概率令 $q=0$（持续性 dropout），使退路可用。
2. **$q$ 有两种来源**：
   - **无标签**：4 个窗口统计量相对该节点训练期分布的马氏距离，阈值取 $\chi^2_4$ 的 0.999 分位数。4 个统计量是分解后回看窗口的均值、对数标准差、中午减夜间，以及"画像一致性" $\log\frac{\mathrm{mean}(x-\pi_{28})^2}{\mathrm{mean}(x-\pi_{14})^2}$。最后一项是后加的：只用前三项时，只能拿到 oracle 收益的约三分之一。
   - **延迟标签**：实测值按日到达，用过去几天的误差估计定理 A1 的最优权重 $w=\mathrm{clip}(\hat{\mathbb E}[e\,d]/\hat{\mathbb E}[d^2],0,1)$（指数加权，半衰期 7 天），在输出空间组合"信任"和"退路"两个预测。
3. **身份用小随机值初始化**：身份经零初始化的 FiLM 进入骨干，两个零因子相乘时梯度恒为 0，身份学不到。修复前的"只有身份"变体实际上等于全局模型。
4. **权重滑动平均**：不做平均时，同一模型换种子的测试 MSE 可差 11%（合成数据），做平均后约 0.5%。

## 2. 合成数据

- 负荷结构：
  - 两类共享日曲线 × 节点特有的周模式：周末系数，以及某个工作日的 4 小时凸起。回看 48 小时时，这部分在窗口中基本看不到。
  - 热泵随气温变化。
  - 光伏：登记后经 Gamma(2, 25 天) 的时滞（平均约 50 天）才投运。

### 分析

1. **节点知识价值很大，但直推式的身份在新节点上失效。**
   - 身份使已训练节点的 MSE 降低 42%，新节点却变差 39%：模型依赖身份，而新节点只有零身份。这与 Electricity 上"未见变量变差 2.8%–4.9%"（实验 3）同一机制，这里因为周模式完全依赖身份而更明显。
   - 身份 dropout 把新节点的损失变为 −5.7%（与实验 3、10 的结论一致）。
2. **归纳式知识（描述 + 近期画像）在新节点上保留了大部分收益**：新节点 −41.9%，已训练节点 −52.3%。加上身份，已训练节点的稳定时段再好 4%，新节点略差。
3. **KCD 带来第二部分收益**：在 NKE + 身份之上，已训练节点 −18%（0.0179 → 0.0146），新节点 −10%（0.0156 → 0.0140）。只把台账当描述信息、不做分解时，登记后 30–120 天的晴天中午比分解差 16%–47%（表 2 最后一行），说明一致分解本身有作用。
4. **投运时间：已训练节点上，时滞先验和投运后验都优于"登记即投运"**（0–30 天 −20% / −27%），后验在 60–120 天也明显更好（−15.5%），接近真实日期的上限（−17.4%）。但有两点尚未解释：
   - 新节点上后验反而更差（+9% 至 +53%），尽管其假设容量误差小于另两种方式；
   - 30–60 天的窗口里，后验的容量误差只有"登记即投运"的三分之一，预测误差却没有更小。

   推测原因是后验在回看窗口中给出分数容量，使分解"模糊"。下一步：逐事件分析；回看窗口改用硬判决（最大后验）；把后验的不确定性也输入模型。这些窗口的事件少，结论需要更多事件确认。
5. **门控：延迟误差门控几乎达到已知变化时刻的上限**（−11.9% / −15.6%，上限 −12.2% / −16.1%）。无标签门控拿到上限的 67%–79%。两者在稳定时段的代价都不超过 0.3%，所以整体上已训练节点仍有 −2.0% 至 −2.9%。
6. **阈值在验证集上选更差**（−2.9%，固定 $\chi^2$ 阈值为 −8.2%）。验证期里几乎没有未记录变化，验证集倾向于"不门控"，这正是推论 A2 预测的情形。
7. **门控对象的选择很关键。** 把全部知识收缩到总体平均时，退路就是"不用任何知识"。训练时没有整体知识 dropout 时，这个退路完全不可用（稳定时段 +600% 以上）；有 dropout 时也比信任差 50%–76%（表 3 最后两行）。所以门控只作用于身份和长窗口画像。另一方面，训练时做了整体知识 dropout 的模型（表 1 最后一行），在未记录变化后反而是所有变体中最好的（相对全局 −49.6% / −33.2%），代价是新节点稳定时段比完整模型差 7.5%。两种 dropout 的作用不同：
   - 持续性 dropout 训练门控的退路；
   - 整体知识 dropout 是正则化，减少模型对节点知识的过度依赖。

   下一步把两者合用。

**结论**：在合成数据上，三个模块都按推导起作用：
- 节点知识的收益与身份缺口一致；
- 归纳式知识解决新节点；
- KCD 加上投运方式处理有记录的变化；
- 门控处理无记录的变化，且几乎没有代价。

需要改进的是：后验在新节点和 30–60 天窗口上的表现；两种 dropout 的组合。

## 3. FeederBW

**设置**（newpapercode `rnk/feederbw.py`）：
- 数据：测量分包 161–200（40 条馈线），1 分钟功率聚合为小时；回看 168 小时，预测次日 24 小时，每天 0 点发布。
- 协变量：辐照、气温（数据集中的事后值），以及日历和巴登-符腾堡节假日。
- 台账的 5 类设备：光伏、储能、热泵、充电桩、蓄热式电暖器。投运后验只用于光伏，其余用时滞先验。
- 时段：训练 2023-04-29 至 2024-02-29，验证 2024 年 3 月，测试 2024-04-01 至 2025-03-31。
- 两种划分：
  - 按时间：40 条馈线都参与训练；
  - 按地点：馈线 161–180 训练，在从未训练过的 181–200 上测试，与先导实验相同。
- 3 个种子；MSE 以 σ 为单位，MAE 为 kW；括号内为相对全局模型的配对变化和更好的种子数。
- 这里没有未记录变化的真值，门控只能检验"没有代价"。

### 分析

1. **在真实馈线上，收益几乎全部来自 KCD**：
   - 按时间划分时，MSE −18%，MAE −7.6%；晴天中午 MSE −25%，MAE −14%。
   - 登记光伏后 60–120 天的晴天中午，MSE −39%。
   - 在从未训练过的馈线上同样成立（MSE −15%，MAE −6%）。这说明"每单位容量的响应 × 登记容量"能迁移到新馈线，是一种归纳式的节点知识。
   - 与先导实验相比：LightGBM 把台账当特征，MAE −5.5%；这里 MAE −7.6%（不同基线，方向一致、幅度更大）。
2. **NKE（描述 + 近期画像，经 FiLM 进入骨干）在 FeederBW 上没有作用**：
   - 按时间划分时 MSE 不变，MAE −1%；
   - 在新馈线上变差 7%。这与先导实验中"训练馈线少时，台账被当成馈线编号记住"一致。
   - 合成数据中 NKE 的大收益，来自回看窗口看不到的周模式。FeederBW 的回看是 7 天，周模式已在窗口内，身份缺口小。这符合命题 1 的条件。

   所以 NKE 需要更强的正则化（台账 dropout、更小的编码器），或只在回看短、节点多的数据上使用。
3. **身份同样没有作用**（−0.0%）：40 条馈线、10 个月训练数据、回看 7 天，身份缺口小。
4. **投运后验在 FeederBW 上没有额外收益**：与"登记即投运"几乎相同（0–30 天 −11.6% 和 −11.9%）。原因可能是一致分解本身对登记时间误差有一定的自我纠正：假设的光伏若尚未投运，这个错误同时出现在回看窗口和预测中，骨干能看到并部分抵消。合成数据的回看只有 48 小时，这种抵消较弱，所以后验在那里更有用。需要用半合成实验验证：在真实馈线上注入已知时滞的光伏。
5. **门控在真实数据上代价为 0**，延迟误差门控在登记光伏后的窗口里略有收益（约 1 个百分点）。由于没有未记录变化的真值，FeederBW 不能检验门控的收益。按 model_direction 的计划，这要靠 Traffic（漂移传感器）、ENTSO-E 2022 和半合成注入。

## 4. 结论与下一步

**目前的证据**：
- **KCD（台账容量 + 一致分解）是最强、最稳的模块**：
  - 合成数据上，在 NKE 之上再 −18%；
  - 真实馈线上 MSE −18%，MAE −7.6%；
  - 在新馈线上同样有效（MSE −15%）。
- **门控（只作用于身份和长窗口画像）**：
  - 合成数据上，未记录变化后的损失被消除到接近 oracle；
  - 真实数据上没有代价。
- **NKE 的描述和画像编码，以及身份**：收益取决于身份缺口。合成数据中很大，FeederBW（回看 7 天）中几乎为 0，在新馈线上还会过拟合。

**对论文主线的影响**：以"台账一致的协变量分解 + 可靠性门控"为核心。NKE 作为在身份缺口大时才起作用的部分，需要正则化，并在 Traffic、Electricity 等身份缺口大的数据上验证。

**下一步**：
1. **投运后验**：半合成注入（真实馈线 + 已知时滞的光伏）；回看窗口用最大后验的硬判决；逐事件分析新节点上的异常。
2. **NKE 正则化**：台账 dropout、更小的编码器；在 Electricity、Traffic 上用 iTransformer 骨干检验（复用已有基线）。
3. **门控的真实数据检验**：Traffic（漂移传感器 840 等）；ENTSO-E 2022；FeederBW 上注入负荷转移。
4. **两种 dropout 合用**：持续性 dropout 与整体知识 dropout。
5. **规模**：FeederBW 全部 200 条馈线；GPU 上换带协变量的全局 Transformer 骨干；5 个种子。
